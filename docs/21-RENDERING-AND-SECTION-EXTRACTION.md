# L012 — JavaScript capture, representative sections and body-evidence scoring

## Objective and acceptance
User approved the Enreal diagnosis improvements and requested live tests of Enreal and VX Real in localhost. Authorized initial HTML/sample → optional isolated rendered DOM → up to nine source-supported keywords and separate initial/rendered audits. Simplest approach: an optional Playwright/Chromium renderer over existing httpx intake, representative heading/description sampling and deterministic scorer fixes. Acceptance: preserve robots/DNS/byte/deadline/permission protections; do not infer body quality from a title; recognise button/div service cards and short meaningful descriptions; represent all nine synthetic roles; cap focus at 100%; keep initial HTML distinct from rendered evidence; test both live sites, UI/export and security regressions. This is an L012 experiment, not T001 completion or deployment.

## Optional runtime
Install `.venv/bin/python -m pip install -e '.[dev,render]'` and, if Chromium is missing, `.venv/bin/python -m playwright install chromium`. The optional extra is `playwright>=1.64,<2`; the verified local version is 1.64.1 and its matching Chromium/headless-shell revision 1248 was already installed. No browser binary was downloaded for this task. Without the optional package/browser, normal HTML scans remain available and JavaScript capture is explicitly incomplete. The UI enables rendering when the package exists; browser availability is checked on the actual attempt. API `render_js` defaults false; the local form opts in. Saved HTML rejects live rendering and stays offline.

This adds a browser dependency only to the optional local audit feature; the production platform stack and strict T001 intake are unchanged.

## Collection and isolation
- Detect a script-bearing page with fewer than 100 readable body characters as a possible JavaScript shell. Render only the submitted primary shell, not every sampled page. Existing eight-page/depth-two/24-request/75-second website limits remain; rendering has an additional 25-second total ceiling.
- Preload at most twelve observed same-host, query-free JS/MJS/CSS assets and their supported literal imports. Each asset passes existing public-DNS pinning, TLS/Host, robots, interval, response and total-byte checks through `AuditIntake.fetch_asset`. Asset attempts share website request/byte/time counters. No external host, arbitrary JSON/API resource, credentialed URL, asset redirect or automatic retry. A robots/network/content-type failure closes the run; the renderer reports incomplete capture rather than trying another route.
- Execute only the preloaded resources in a fresh non-persistent Chromium context with `offline=True`, service workers blocked and downloads disabled. Route handling fulfills only the original main HTML and allowlisted script/styles; all other requests abort, never continue to the network. WebSockets close. The browser's environment excludes the server credential; DNS background networking is disabled and V8 heap is bounded to 128 MB (not a guarantee of total browser process memory).
- A restrictive local CSP blocks connects, frames, workers, forms and external assets. No user browser profile, cookies, password store or session is reused. No screenshots, raw HTML, model reasoning or credentials are persisted by the application.
- Some current apps initially show a navigation gate. If text is short, allow at most one explicit content-navigation button (services/solutions/products/business consulting/workforce labels), outside a form, inside the offline copy only. Never book, submit, sign in, purchase or follow arbitrary controls. Record the label and resulting same-host location, and require the existing robots policy to permit that resulting path before accepting the DOM. This is interactive content evidence, not a promise that crawlers automatically perform that interaction.
- Snapshot DOM up to 1 MB after stripping scripts/forms/frames/embedded objects. Record raw/rendered hashes, original URL, resulting location, acquisition mode and limitations. API-dependent, cross-origin or unsupported chunk-loading sites may remain incomplete. Do not silently fall back around a policy block.

Implementation references: [Playwright isolated contexts](https://playwright.dev/python/docs/api/class-browsercontext) and [request routing](https://playwright.dev/python/docs/api/class-route). Offline routing is exercised by an actual Chromium integration test, not assumed from mocks alone.

## Evidence and extraction
Initial HTML audit remains the original 55-check `verified-page-0.4` report. A successful render adds a separate `rendered_audit`; the UI defaults to that view when available and offers an evidence selector. Export retains both. Rendered data does not establish layout/mobile performance, crawler-specific edge access, indexing or citations. Topic source URLs/hashes refer to the actual effective DOM, with the raw source hash and acquisition mode retained.

Representative excerpts pair distinct service headings with descriptions from bounded local sections, button cards and div cards, rather than taking only the first four headings and first paragraphs. Prioritise nine distinct service/role sections while preserving the existing 24 KB provider-input ceiling and one bounded Kimi call. After repeated live 90-second completion timeouts, the provider wall deadline becomes 180 seconds without changing the 6,144-token/ten-attempt bounds; the UI states this delay. Metadata records received bytes and answer/reasoning character counts, never text, to distinguish slow generation from collection failures. Descriptive heading/card candidates take priority over generic hero text. Meaningful terms such as service/support/learning are no longer discarded as connecting words; accessible home/logo labels and the hostname without www help suppress brands in local fallback.

The page-text block list excludes headings/titles, navigation, footer, forms and hidden/script content. Quotes locate actual body paragraphs or their small local section; there is no artificial quote-as-body fallback. A meaningful short body description can qualify without eight words. Section context cannot absorb an unrelated multi-heading hub. Focus divides matched body content by extracted body content and is bounded at one; metadata alone creates no keyword content score. If no substantive content can be captured, skip the paid provider call and explicitly show limited capture with no filler cards.

Versions: local `site-topics-0.4`, Kimi `kimi-keywords-0.3` or `kimi-semantic-0.4`, prompt/cache version `kimi-semantic-selection-0.4`. Technical point budgets and the 0–10 units remain unchanged. Changing acquisition/context rules is a methodology change, not a demonstrated website ranking improvement.
