# L010 — Meaning-based keyword readiness

**Scale update:** L011 caps the current grid at nine and rescales keyword/component/baseline scores to 0–10. The L010 figures below describe the historical hundred-point version. See [current scale and audit](20-VERIFIED-READINESS-SCALE.md).

## Task and acceptance
User requested understanding similar meanings rather than exact keyword matches, then a new VX Real test. Input: the existing authorized public-page sample and optional server-side Kimi selection. Output: separate SEO/GEO keyword scores, typed source references, equivalent/related judgments and a same-content phrase baseline. Simplest approach: extend the existing single structured Kimi call and deterministic scorer; no embedding service, dependency or additional model call. Acceptance: paraphrases earn supported credit, related meanings earn partial credit, invalid references and explicit negative service evidence are rejected, point budgets remain 100 per group, and live browser/export verification succeeds.

## Matching and points
The server supplies bounded title, heading, body and link-label segments with IDs. Kimi proposes short site-derived keywords and identifies up to four semantically equivalent or related segments per keyword, with compact rationale and quotation output. The server resolves IDs to its own text, type, URL and content hash; unknown IDs are dropped and model-supplied source types/text are forbidden. Source references validate provenance; semantic equivalence and business relevance remain model judgments requiring review.

An equivalent match can earn full alignment credit; a related match earns half credit. Title and heading alignment each contribute up to ten points; descriptive link alignment contributes up to twenty. Body annotations identify explanation, process, detail and scope, allowing useful paraphrases to contribute without fixed trigger words. Each SEO/GEO group still has five components capped at twenty points each. Repeated annotations cannot stack credit. Related-only body support, without literal substantive support, is capped at half credit per body component. Equivalent body/headings can supply nearby context within a small section; unrelated sections are excluded.

Explicit English negative offerings such as “we do not offer” are excluded from positive service evidence. This is a narrow guard, not comprehensive multilingual negation understanding. Semantic matches are optional: local-only mode and absent annotations retain phrase/quotation-context matching with an explicit label. Saved HTML stays offline. Technical `weighted-page-0.3` checks remain unchanged.

## Comparison and uncertainty
Reports with semantic matches use `kimi-semantic-0.2`. Each Kimi-selected card also includes scores calculated with semantic annotations removed, using the same fetched pages and identical keywords. The UI labels this a method comparison, not a website improvement. Page choice can differ between the two methods when evidence supports another sampled page. A higher score demonstrates recognition under this rubric; it does not establish higher Google rankings, AI citations or factual correctness.

Source-backed semantic judgments can still be wrong or incomplete. The typed excerpt budget samples only part of each page, so omitted passages receive no semantic credit. Keep intent (service/project/research), quotations, individual components and human review visible. Search demand, volume, competition, Google positions and actual AI citations remain unmeasured.

## Bounds and costs
Reuse the existing eight-page/depth-two/24-request/75-second website collector, DNS pinning, TLS, per-host robots policy, byte caps and owner consent. Provider input remains at most 24,000 UTF-8 bytes; typed segments now share an 1,800-character page budget. One uncached completion, ten attempts per process, five cached reports for ten minutes, no tools, redirects or automatic retries. K3.1 output cap increases from 4,096 to 6,144 completion tokens (including reasoning), and provider deadline from 45 to 90 seconds to accommodate annotations. Explicit legacy K2.6 retains its existing 2,400-token output cap. K3.1 uses the [documented SSE transport](https://platform.kimi.ai/docs/api/chat) after non-streaming connection failures. Decoded stream bytes are capped at 2 MB including framing, individual frames and assembled final JSON at 128 KB, with the same 90-second total provider deadline. Reasoning deltas are discarded; a completed stream and a successful finish reason are required. Standard JSON responses retain the 128 KB cap. Final usage chunks preserve actual token accounting. Provider usage is recorded; dollar cost remains unknown and charges may apply. Credentials stay in server environment only.
