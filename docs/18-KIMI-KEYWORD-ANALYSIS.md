## Authorization, limits and costs
- API `use_kimi` defaults false. The live UI enables/checks an explicit Kimi option when configured, explaining that extracted public text goes to the provider and charges may apply. Owner authorization remains mandatory. Saved HTML is offline: requesting Kimi there returns 400; no file is sent externally.
- Existing authorized website collection keeps eight pages/depth two/24 requests/75 seconds and its DNS/TLS/robots/byte guards. A blocked first page never reaches the provider. Collected partial scope is disclosed.
- One completion per uncached scan; no tools, file uploads, provider-side URL fetches, automatic retries or provider redirects. Static HTTPS endpoint and trust_env=false prevent request/proxy redirection of the Authorization header.
- Send page IDs plus at most 2,400 characters per page, max eight pages and 24,000 UTF-8 bytes total, plus the fixed system prompt. No HTTP headers, cookies, raw HTML, source URLs or form values; public email-like text is masked. The cleaned text is not a comprehensive PII scrubber; this mode is for authorized public pages only.
- Completion max 2,400 tokens, response max 128,000 decoded bytes, provider wall deadline 45 seconds. At most ten completion attempts per server process, including failures. No public endpoint or scheduling.
- Cache at most five successful reports in memory for ten minutes using prompt/model/site content hashes; cache hits make no completion call. Usage includes actual provider input/output token counts where returned and attempts remaining. Metadata-only logs omit prompts, raw outputs, headers and secrets. Cancelled/failed requests may still be billable.
- USD estimate is explicitly null because a reliable numeric provider rate was not available in the fetched pricing table. Report that billing must be checked at the provider; never assert free use, zero cost or an exact invoice amount. Limits cap tokens/calls rather than promising a dollar ceiling.

## Evidence and scoring
The model proposes up to ten 2–5-word keywords, up to two natural query phrases, an intent (service/project/research), rationale and one/two supplied page-ID/quotation references. It must avoid client/company names, slogans, incidental locations and unsupported capability or popularity claims. Website content is untrusted data and cannot change prompts, tools, credentials or endpoint.

The top-level list is bounded; Pydantic validates each suggestion independently, so one malformed item does not discard valid neighbours; the server checks that 30–240-character quotations occur in the supplied excerpts (normalized whitespace/case), resolves only supplied IDs to original URLs/hashes and drops unsupported/near-duplicate candidates. If none survive or provider output is malformed/truncated, fall back to site-derived local suggestions with a visible reason. A literal quote match establishes provenance only: a human still reviews whether the suggested phrase is relevant and whether the business claim is true. Model rationale is an unverified draft.

Kimi does not generate scores. Existing five SEO/five GEO signal checks score the selected referenced page, using matched quotations to locate their small semantic section when a paraphrased keyword is absent literally. Adjacent detail in that section is included; a short citation is not treated as the entire service description. Title/heading/link matches still use the suggested phrase. The report version is `kimi-keywords-0.1`, distinct from lexical `site-topics-0.2`; changed scores are not demonstrated website gains. Page hashes, supporting quotes, rationale, intent, usage and provider/cached/fallback state are exported. Demand/volume/competition remain null/unmeasured, and actual rankings/AI citations remain untested.
