# First testing round

Use the [setup guide](TEAM-SETUP.md) for commands. Keep findings brief; explore further where you see value.

| Check | What to record |
| --- | --- |
| Start locally | Operating system, Python version, source revision and any setup problem |
| VX Real basic scan | URL, date, options and whether the report completes with Kimi off |
| Topic relevance | Which suggestions match real customer needs; which are broad, project names or unsupported |
| Scoring clarity | Whether readiness, evidence gaps and actual visibility are clearly distinguished |
| Evidence and actions | Whether findings point to the right page and a useful next action |
| ESGtrace one-off scan | Capture mode, reviewed URL and any access/JavaScript limitation; never save under another pilot |
| Optional Kimi test | Approved key/model, call outcome and relevance; keep credentials and account data private |
| Report history | Save/reopen a VX Real report; confirm it reopens without another scan or paid call |
| English/Traditional Chinese | Test only permitted sites; note irrelevant or ambiguous suggestions |
| Client needs | What the client wants to achieve, what help they need and what they would pay for |
| Knowledge / PrivateKB discovery | Identify approved versus confidential information and whether private retrieval adds value; no sensitive-document upload during basic testing |
| Proposed first improvements | Business reason, evidence, required access and how the result could be measured |

Use GitHub Issues for bugs and the [feedback CSV](templates/TESTING-FEEDBACK.csv) for a compact review. Do not interpret unavailable access, missing measurements or a blocked scan as zero search visibility. Do not test live enquiry submission, change client sites, enable new accounts or deploy publicly during this round.

A successful first round establishes what works, what is misleading and what to improve next; it does not need to prove commercial effectiveness in a few days. Collect comparable baselines and allow suitable observation periods for outcome testing.
