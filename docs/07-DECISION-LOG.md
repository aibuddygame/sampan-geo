## D010 — 2026-10-16 — Bounded private intake (accepted for P01-2)
Use a sequential private httpx service restricted to the exact VX Real HTTPS origin. Pin each connection to a validated public DNS address with the original Host and TLS name; a check followed by an ordinary hostname fetch would leave a DNS rebinding gap. No proxies, automatic redirects or retries. Failures close the run.

Require an operator permission/terms review record before requests. Use a deliberately restrictive robots subset: unavailable/redirected/malformed policies block, all applicable disallows apply, and Allow overrides are ignored. This may overblock compared with RFC 9309; missing robots is not automatically permission. Bounds and integration requirements are in [11-SAFE-INTAKE.md](11-SAFE-INTAKE.md). Alternatives: general multi-domain crawler or public fetch API; deferred because neither is needed for T001. No stack change or real-site authorization is implied.
